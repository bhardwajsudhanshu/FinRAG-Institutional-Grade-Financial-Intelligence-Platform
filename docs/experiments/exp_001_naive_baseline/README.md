# Experiment 001 — Naive Baseline

**Status:** Defined (will be run in Week 1)
**Date:** 2026-09-05

## Hypothesis

A naive fixed-size chunking strategy (512 tokens, 50-token overlap) with
cosine-similarity retrieval over ChromaDB and Gemini 2.5 Flash generation
will achieve:

- **Hit@5 ≥ 0.50** (at least half the time, the right chunk is in the top 5)
- **Context Recall ≥ 0.40** (RAGAS)
- **Faithfulness ≥ 0.85** (no hallucinations, just retrieval + citation)

These are the **floor** numbers. Every subsequent chunker, retriever, and
re-ranker must beat them.

## Setup

| Component | Choice |
|-----------|--------|
| **Chunker** | Naive fixed-size, 512 tokens, 50 overlap, `cl100k_base` encoding |
| **Embedder** | `text-embedding-005` via Vertex AI (768-dim) |
| **Vector DB** | ChromaDB (in-memory, persistent to `./data/chroma`) |
| **Retriever** | Cosine similarity, top-K=5 |
| **Generator** | `gemini-2.5-flash` via Vertex AI |
| **Eval set** | 200 Q&A pairs (100 factual, 50 multi-doc, 50 numeric), generated by Gemini 2.5 Pro with cited source spans |
| **Metrics** | Hit@5, MRR, Context Recall, Faithfulness, Answer Relevancy (RAGAS), p50/p95 latency, $/query |

## Predicted failure modes (pre-mortem)

These are the things we expect to go wrong with the baseline, so we know
what to look for in the analysis:

1. **Risk factors split across chunks**: A "Risk Factors" section that
   spans Items 1A and 7 might have its key clause in a chunk that ends
   mid-sentence. Late chunking should help.

2. **Year ambiguity**: "Apple's revenue in 2023" — does the user mean
   FY2023 (ended Sep 2023) or calendar 2023? Filings span calendar
   years. We expect ~20% of "year" queries to retrieve the wrong year.

3. **Numeric tables not parsed**: The 10-K's financial statements are
   tables in HTML. Our parser flattens to text, so the structure
   ("Net sales: $383,285" vs "Net sales 2022: $394,328") may lose the
   column headers. Document-aware chunking should help.

4. **Cross-Item references**: "See Item 7 for a discussion of..." is
   common. Naive chunking can't follow these. RAPTOR or sentence-window
   may help.

5. **Hallucination on out-of-corpus questions**: "What is the CEO's
   salary?" is in DEF 14A, not 10-K. The system may hallucinate an
   answer. CRAG should help.

## Status

This is the **baseline**. It's deliberately simple. If the numbers are
much better than expected, the eval set is too easy. If much worse, the
parsing is broken.
