# Experiment Results Schema

Every experiment in `docs/experiments/exp_*` produces one row appended to
`results/experiments.csv` when `make eval-nightly` runs. The schema is
frozen by ADR-003 and lives at the top of `finrag/cli/eval.py`.

## Columns

| Column | Type | Description |
|--------|------|-------------|
| `exp_name` | str | Folder name, e.g. `exp_001_naive_baseline` |
| `timestamp` | ISO8601 | When the row was written |
| `n_questions` | int | Q's in the eval set used for this run |
| `n_filings` | int | Distinct (ticker, filing_date) pairs |
| `n_chunks` | int | Chunks in the in-memory index |
| `context_recall` | float | RAGAS metric, in [0, 1]; higher is better |
| `faithfulness` | float | RAGAS metric, in [0, 1]; higher is better |
| `answer_relevancy` | float | RAGAS metric, in [0, 1]; higher is better |
| `hit_at_5` | float | Custom, fraction of Q's where source chunk is in top-5 |
| `citation_accuracy` | float | Custom, fraction of Q's with correct citations |
| `mean_latency_ms` | float | Custom, mean wall-clock per Q |
| `total_cost_usd` | float | Total LLM + embed cost for the run |

`None` (rendered as empty cell) means the metric was skipped or could
not be computed. For RAGAS, this happens if the judge LLM call failed;
for custom metrics, the value is always populated.

## Per-Q details

Each run also writes a JSONL at `results/<exp_name>/per_question.jsonl`
with one record per Q. Fields:

```json
{
  "qid": "q_0001",
  "question": "What was Apple's revenue in FY2023?",
  "ground_truth": "Apple's net sales were $383.3 billion.",
  "source_chunk_id": "AAPL_2023-11-03_item_7::0003",
  "qa_type": "lookup",
  "retrieved_chunk_ids": ["..."],
  "generated_chunk_ids": ["..."],
  "answer": "Apple's net sales for fiscal year 2023 were $383.3 billion.",
  "latency_ms": 1234
}
```

## How to read the leaderboard

`results/leaderboard.json` (regenerated by `make leaderboard`) tracks the
winning experiment in each of 5 categories:

- `chunking`: which chunking strategy has the best context_recall
- `vectordb`: which vector DB has the lowest p95_latency (column will be
  added once Phase 3 is reached)
- `retrieval`: which retrieval strategy has the best context_recall
- `reranker`: which re-ranker has the best hit@10 (column will be added
  once Phase 4 is reached)
- `end_to_end`: which full pipeline has the best faithfulness

Until we have a contender in each category, the `winner` is null.
